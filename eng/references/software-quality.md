# 软件质量

在既有模块结构内约束实现细节、契约精度、错误回退、改动收尾、测试与交付产物。跨模块状态/依赖/运维架构见 `software-architecture.md`，数据库事务与迁移见 `database-engineering.md`。

## 可读性与表达品味

- **命名表达领域现状**：同一领域概念保持一致命名，不用 `data`、`manager` 掩盖混杂职责；短小局部变量遵循语言惯例即可。
- **不把改动过程写进代码**：命名、注释和文档只描述代码**现在是什么、为什么受此约束**，绝不写 `handlerV2`、`newParser`、`fixedTotal` 或“修复后 / 改为 / 不再”这类合并即过时的提交说明式措辞。
- **直白优于精巧**：使控制流、外部调用和副作用一眼可辨，避免隐式初始化顺序或需大段注释辩护的复杂写法。

## 契约精度、错误与回退

- **消除边界歧义**：时间明确时区、时间点或时长；金额与数值明确单位、范围、精度和舍入规则；文本与序列化边界明确编码和有损转换约定；多布尔组合改用具名结构或枚举。
- **区分失败语义与可排障上下文**：明确区分缺失、空集合、未加载、权限拒绝、超时与取消，承诺“已保存”前等待真实持久化确认，不用空捕获或无条件默认值吞掉错误。包装或记录错误时保留原始根因链（如 `cause`）及定位必需的动作与对象 ID（脱敏，不含密钥、内部堆栈/SQL 或完整私密载荷），避免无上下文的笼统报错与循环内高频刷屏日志。
- **回退何时改变选择**：仅在产品允许陈旧读取且调用方能识别时效标记时，才用带时间戳的缓存等回退（如商品浏览）；一旦超出时效、权限变更，或结果将驱动预留、扣款等不可安全撤销的决策，必须立即暴露失败，恢复正常后及时退出降级。重试仅限幂等安全操作，设有限次数/超时并响应取消。

## 改动的收尾与工具边界

- **通读完整差异**：收尾前逐处核对 diff 是否对应本次目标，清理临时日志、注释掉的废代码、无主 TODO 及编辑器顺手引入的无关格式变动。
- **准备性重构与行为改动分开**：需先调结构再改行为时分步进行，便于独立验证和回退，不为无关区域顺手重构。删除看似多余的旧代码前，先查历史提交、测试与外部调用方。
- **不用压制指令掩盖真实问题**：遇到类型报错、lint 警告或失败测试（如字段可能为 `undefined`），先处理真实缺失或契约边界，不用 `as any`、`@ts-ignore`、放宽规则或跳过测试让工具闭嘴。确属已核实的工具误报时，压制限定在最小行范围，就地注明原因和移除条件。
- **生成物经源头工具更新**：锁文件、代码生成物和构建产物由包管理器或生成器更新，不手改；出现无关生成差异时先查清原因。

## 行为测试与验证强度

- **测契约而非实现细节**：断言公开行为与业务不变量，不绑死私有方法调用顺序或大块无意义快照；异步测试等待可观察条件并设超时，不用固定长等待碰运气。
- **覆盖真实约束机制**：纯逻辑用单测；唯一性、并发竞争、事务回滚和行级权限须在包含真实约束机制的最低层验证，把核心机制 mock 掉的测试不能证明约束生效。
- **按风险调整验证强度**：改一行静态文案核对内容与呈现即可收尾；改一行金额、租户条件或并发写入，必须补充对应边界验证。缺少必需环境或权限时如实说明缺口，不用无关绿灯充数。

## 实际交付物与授权边界

- **交付物与配置凭据卫生**：构建依赖从仓库锁文件确定，缺失必需配置在启动/使用前显式报错；新增配置项同步更新校验 schema 与 `.env.example` 等模板。严格隔离前端公开构建变量（如 `NEXT_PUBLIC_*`、`VITE_*`）与服务端私密配置，绝不将真实凭据写入源码、测试夹具或快照。改动打包、依赖或资源路径时，在干净或隔离环境验证实际生成的产物可用。
- **动作级授权与租户隔离**：在真实动作与资源边界校验权限，从可信认证主体推导租户与所有者——客户端传入的 `tenant_id`、`org_id`、`user_id` 和对象 ID 只是待校验声明，隐藏按钮或内部路由不等于授权。筛选/排序列名使用允许列表；Webhook 先验签防重放再做幂等写入；指标标签保持低基数（不含原始用户 ID）。

## 示例：幂等与租户范围

仅在受影响路径存在对应不变量时参考：

### 重试库存预留

- **反例**：先查 `requests[key]`，不存在则扣库存再写结果——并发请求会同时通过查询，中间崩溃还会留下未记录扣减。
- **做法**：从认证上下文取租户，在单个数据库事务内占用唯一键 `(tenant, operation, key)`（绑定载荷指纹）、执行带条件库存扣减并保存结果；重复键按冲突语义返回已提交结果，同键不同载荷直接拒绝。外部支付或消息不可放入本地锁内，须配合服务商幂等键或持久化 Outbox。
- **验证**：对真实数据库发起并发相同请求、丢弃响应后重试、同键异参请求及提交前故障注入，核对仅扣减一次且无残留。

### 跨租户文档访问

- **反例**：仅在列表接口过滤租户，更新接口直接 `findById(input.id)` 修改。
- **做法**：所有读写条件、缓存键、导出和后台任务统一绑定已认证主体的可信 `tenant_id`。
- **验证**：用租户 A 凭据操作租户 B 的对象 ID 断言拒绝且 B 数据未变，同时保留 A 操作自身对象的成功用例（防“全部拒绝”假通过）；启用 RLS 时须用真实应用角色而非超级用户测试。
