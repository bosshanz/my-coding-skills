# 设计

帮助用户看清信息、顺畅操作、理解状态变化并安全恢复，让视觉表达服务具体任务。用户的设计要求、既有设计系统、平台惯例和无障碍下限优先于个人风格偏好。

## 从具体问题出发

改动前先查看现有界面、真实内容、代码或运行状态，明确用户任务、当前主要障碍与预期改变；新产品尚无界面时基于代表性内容推导，标明待验证假设。把“不好看”“不顺手”拆解到可处理的维度：

- **理解**：信息顺序是否匹配决策顺序？名称、状态与层级是否清晰可辨？
- **操作**：路径、控件和默认值是否契合任务频率与目标设备？
- **恢复**：部分失败、取消、返回或中断后，能否看清结果、保留已有选择与输入并安全重试？
- **视觉表达**：对齐、间距、密度、配色和字体是否支撑重点与产品气质？

优先解决阻塞、误导或丢失用户工作的问题，再打磨操作负担与视觉细节（例如频繁弹窗打断逐项核对时，先改用保留列表上下文的侧栏/详情区，而非只调弹窗圆角）。纯视觉探索无需重做产品立项论证；仅在缺失信息会实质改变设计方向且无法从现有材料推断时提问。

## 按决策查阅参考

只读取当前决策需要的那一份参考，不必整套加载：

| 参考 | 适用决策 |
| --- | --- |
| `references/interaction.md` | 任务流程、列表/卡片/表单模式选择、焦点与键盘、异步反馈、部分失败重试、工作保留与恢复；含浏览与比较、表单依赖、动作可逆性成对案例。 |
| `references/design-direction.md` | 视觉层级、网格对齐、密度、字阶、色彩角色、文案与设计语言；字号/行高/间距起点，不随风格妥协的对比度（正文 ≥ 4.5:1）与目标尺寸下限；含品牌约束成对案例。 |
| `references/animation.md` | 动效目的、变化对象、时序参数、快速中断与离场焦点、减少动态效果替代方案；含点击弹出、路由过渡及频率/无障碍成对案例。 |

参考中的真实反馈、工作保留与无障碍下限必须满足；布局模式、参数起点和风格倾向按具体约束取舍。

## 交付、验证与记录

- **按请求范围交付**：仅要求设计或先看交互时，交付布局/流程、关键状态转换、恢复策略与取舍，不抢跑视觉稿或代码；获准实现时，前端工程与状态原则配合 `eng`（遵从用户对 Skill 的选择）。产品文案使用用户可理解的领域语言，不暴露无关技术细节。
- **用真实内容与对应手段验证**：用长文本、空状态、窄屏等代表性内容渲染检查层级与几何对齐；通过实际交互检查流程、焦点和错误恢复；在正常速度及快速连点/反向中断下检查动效（慢放仅用于排查跳变）。如实说明依据、代价与未实际运行的环节。
- **实质变更同步最小记录**：实质改变产品体验或业务流程时，按需维护最小产品记录（优先复用项目既有设计文档，缺省 `docs/product.md`，区分已确认规则、设计建议与待验证假设）。局部调整不新建文档；与现有实现或要求冲突时明确指出。

**边界：** 本 Skill 不提供前端架构、性能调优或测试框架规范，不改变既有授权，也不自动调用其他 Skill。
