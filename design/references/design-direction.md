# 设计方向

依据用户任务、内容、已有产品和平台惯例选择视觉表达。开放的概念设计可以建立鲜明身份；已有产品和高频工具通常更需要连续、可读和易于操作的界面。视觉选择要说明它帮助用户看见、理解或完成什么。

<a id="流程构思探索规划评审构建再评审"></a>
## 从任务和内容确定方向

先找出页面的主要任务、用户首先需要辨认的信息、可用的真实内容和既有约束。区分已观察到的界面问题与关于用户的假设；只有缺失信息会改变视觉选择时才追问。开放探索可比较少量有实质差异的方向，例如强调内容本身、强调操作效率或强调品牌氛围；写清各方向适合的场景与代价，再选一个继续。已有系统优先检查复用，而不是把重新设计当作默认目标。

让布局承载信息关系。首屏应让用户看见当前任务最重要的主张、内容或动作；标题、图片、实时演示和交互片段只是实现手段。数字、标签、分隔线和编号必须有可解释的含义；仅当内容确有顺序时才用序号。表现性元素可以集中在最有识别度的主题材料上，不要求每个区域都重复装饰。

<a id="设计原则"></a>
## 视觉基本功

- **层级与密度：** 决定用户先看什么、接着比较什么、最后操作什么。用位置、尺寸、字重、留白、颜色或容器关系建立层级，避免同时把所有元素做成焦点。信息密集的工具可缩小间距、增加可见行数，但须保留清楚的分组、对齐和可点击范围；展示页面可用更宽松的节奏突出少量内容。
- **网格、对齐与间距：** 从内容宽度、阅读顺序和重复对象推导列数与断点。标题、正文、控件和数据列应沿少数明确的对齐线组织；间距变化要表达组内、组间和章节之间的关系。窄屏先确定阅读与操作顺序，再重排列和容器，不机械压缩桌面版。
- **字阶与文字：** 依据内容和既有系统选字体家族，规定标题、正文、辅助信息和数据的相对层级，检查行长、行高、字重和数字对齐。中英文混排要实际检查换行、标点、英文长词、数字与单位；显示字体若削弱长段文字或密集数据的可读性，应只用于合适的短标题。
- **色彩角色：** 区分背景、表面、文字、边界、强调、交互状态和语义反馈，并检查它们在不同层级上的可辨性。颜色数量取决于已有系统、内容复杂度和状态需求，不设固定配额。不要只靠颜色传达错误、选中或进度。
- **图像与图标：** 图像应提供真实产品、对象或氛围证据；裁切和文字叠放要照顾主体与窄屏。图标用熟悉的含义帮助识别动作，配合文字或清晰上下文；同类图标的线条、尺寸和对齐保持一致。没有信息贡献的插画与图标可省去。

用实际内容检查方案：最长的标题、空数据、较多列表项、中文与英文混排、长数字、较窄视口，以及用户需要放大文字时的布局。占位文案只能帮助构思，不能证明最终层级和换行成立。

<a id="对齐与细节"></a>
## 对齐与细节

标准：

- **共享对齐线：** 组件沿少数明确的边缘、基线或中线对齐；新增元素先找已有对齐线，而不是另起一条。
- **光学居中：** 图标加文字、播放按钮、数字和不对称字形，按视觉重心而非几何中心对齐；做光学补偿时说明原因。
- **间距节奏：** 间距取自已有 token 或比例；不在其中的数值需要具体理由。
- **同级一致：** 并列的卡片、列表项，以及同一行的输入框、按钮和选择框，共享高度、内边距和圆角。
- **嵌套不漂移：** 容器嵌套时，内边距叠加不应让内容边缘偏离外层对齐线。
- **表单列对齐：** 同一表单中的标签列和输入列分别对齐。

发现偏差（按改动范围和风险选择，局部样式修改只检查受影响的元素与尺寸）：

- 在目标视口或窗口尺寸中渲染受影响的界面；布局会随宽度变化时，检查最窄和最宽两种尺寸，使用真实长文本和空数据。
- 测量相邻元素的实际几何并写明偏差值，不靠目测判断。Web 可用 `getBoundingClientRect` 或开发者工具；原生界面使用平台的视图层级或布局检查工具。
- 局部细节放大截图检查。同级元素间无法解释的 1–4px 偏差通常应修正，有意的光学补偿除外。
- 只扫一眼截图不能证明已经对齐。

## 形成一致的设计语言

先识别产品已有的字体、颜色、间距、容器、控件与动效规则。不要只复制 token 数值，还要理解它们表达的关系：强调色用于哪些动作，表面与边界如何区分层级，控件在默认、聚焦、悬停、禁用、处理中、成功和错误状态如何保持可辨，动效怎样说明同一对象的状态变化。重复元素出现不一致时，先判断是遗漏、真实语义差异还是平台差异，再决定统一或保留。

没有既有系统时，先用少量可复用的角色与组件建立一致性，再按真实内容扩展。局部变体需要明确用途，例如危险操作、沉浸式内容或紧凑数据表；说明它与基础样式共享的字体、间距或状态规则，避免每个页面都生成一套新语言。品牌网站可以把表达力放在主题图像与标题；高频工具通常优先扫描效率和稳定状态；原生界面应先尊重平台控件、文字缩放与窗口行为。这些是判断起点，不是风格禁令。

动效也属于设计语言：同一类打开、切换或反馈应有相近的空间关系与节奏。具体的时序、手势和减少动态效果处理见 [动效参考](animation.md)；视觉稿中至少说明哪些对象变化、哪些反馈仍需清楚可见。

## 克制与自我评审

用真实内容和目标尺寸查看渲染结果，先检查最重要的信息或动作是否容易找到，再检查对齐、换行、裁切、状态和细节。装饰若争夺注意力、造成误解或挤压内容，就减少或移除；品牌表达有明确作用时可以保留。把发现写成可定位的问题，例如“窄屏上的辅助标签比主操作更醒目”，并修改对应的层级，避免用“更高级”作为无法检验的目标。

缺少约束时容易落入常见默认倾向：泛用的紫蓝渐变、把所有内容包进卡片、居中主视觉加三张特性卡、用 emoji 充当图标、每个区域都加装饰、滥用阴影和圆角。这些不是禁令，采用时说明它在当前产品中的作用。

完成受影响状态与尺寸的检查、解决具体不匹配后收尾。截图说明布局，不证明用户已理解；需要判断发现、比较或操作是否顺畅时，再走对应任务并说明观察范围。

## 设计中的写作

文字帮助用户理解和使用界面，也是决定布局的内容。按用户能控制和识别的对象命名，使用平实语言说明功能；“通知”通常比系统内部的“webhook 配置”更容易理解。控件应准确说明操作结果，例如“保存更改”；同一动作在按钮和反馈中使用一致名称。

失败与空状态应说明发生了什么、下一步能做什么；语气应匹配品牌和受众。标签负责命名，示例负责演示。写完后把真实文案放进界面，检查长度、换行、截断和窄屏顺序。

<a id="calibration-examples"></a>
## 选择示例

- **营销概念：** 野外录音主题可能适合独特声音意象和表现性字体。选择一种相关焦点处理；每张卡片都放通用波形只会增加无意义装饰。将渲染结果与实际主题、文案比较。
- **已有管理工具：** 保留字体、控件和导航。用逐项状态和清晰重试改善发布部分完成的结果；换一种标题字体无法解决该任务。同时检查渲染层级和重试行为。
- **原生桌面流程：** 遵循平台控件和内容可读性。设置面板不需要醒目首屏或复杂入场。除外观外，还要检查焦点、缩放窗口和反复使用。

<a id="paired-examples"></a>
### 成对案例：相同内容，改变既有品牌约束

共同条件：为“野外录音档案”设计可在桌面和手机浏览的首页。两版使用相同内容：标题“听见城市边缘”，介绍“记录城市与自然交界处的日常声音”，以及三段录音《雨后的高架》（北京，02:14）、《清晨的渡口》（上海，03:08）、《夜行列车》（广州，01:46）；每条都有播放动作。用户需要发现录音并选一条播放。只改变是否存在必须沿用的品牌系统；下列选择是设计推演，未执行用户研究。

| 条件 | 具体方案与理由 | 代价、改判条件与验证 |
| --- | --- | --- |
| **没有既有品牌约束** | 以录音地点的实景照片和清晰的标题建立主题；首屏给出一句介绍与第一条录音的播放入口，下面用统一列表显示三条的地点、时长和播放动作。用一个有辨识度的标题字样，正文与元数据保持易读；声音波形仅在播放进度确有意义的位置出现。这样能让内容本身建立身份，同时保留比较三条录音的能力。 | 实景素材的质量和裁切成本较高，标题表达可能挤占窄屏空间。如果素材无法准确代表录音、用户主要是反复查找特定条目，改用更紧凑的列表与搜索入口。用真实标题和照片检查宽窄屏渲染、文字对比与裁切；通过实际点击确认播放动作易找，未做此检查前不声称有效。 |
| **已有品牌约束** | 假定现有品牌已规定深蓝主色、无衬线字阶、圆角控件、摄影风格和播放按钮状态。沿用这些规则组织同一标题、介绍与三条录音；首屏仍突出一条可播放录音，列表沿用现有卡片和状态样式。辨识度来自品牌摄影与声音内容，减少新字体和新容器带来的割裂。 | 沿用组件可能限制首屏的表现力，既有卡片也可能容纳不下地点和时长。如果真实内容暴露出换行或状态识别问题，先在品牌规则内调整卡片密度与元数据布局；只有规则确实无法满足任务时再提出局部变体。用同样内容和视口检查层级、换行、对比与按钮状态，并走一遍播放操作；与无约束方案比较时不要把品牌约束以外的内容或任务一并改动。 |

渲染检查只能说明可见布局与层级；实际操作才能检查发现与播放流程。以上案例展示设计取舍，不代表已完成用户研究或验证。
