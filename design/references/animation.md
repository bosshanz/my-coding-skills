# 动画

有实质动效工作时参考：微交互、进入与退出、手势驱动界面，以及动画审查或改进。视觉方向见 design-direction.md；状态、输入与恢复行为见 interaction.md。先确定动作要帮助用户理解什么，再决定是否需要运动。

## 动效判断顺序

判断有实质意义的动效时，沿 **目的 → 变化对象 → 前后状态 → 时序与空间关系 → 中断 → 替代行为** 梳理选择。只展开影响当前任务的内容，不要求逐项输出报告。

1. **目的**：是确认操作、解释状态关系、提示进行中，还是装饰？若移除动画不损害理解或反馈，可以不加。
2. **变化对象**：明确哪个对象改变，哪些内容必须稳定，避免整个页面陪着一个控件运动。
3. **前后状态**：说明触发前、进行中、完成、失败与取消时用户看到什么，以及何时可继续操作。
4. **时序与空间关系**：根据距离、层级、方向和触发点判断是否需要连续过渡。先保证响应及时，再调节节奏。
5. **中断**：快速反向、重复触发、导航离开、拖动取消时，从当前可见状态接向新目标；处理离场对象的焦点、点击和遮挡。
6. **替代行为**：减少动态效果或动效不可用时，静态界面仍须传达结果。文字、图标、对比、位置或可访问状态可承担反馈。

## 核心动效参数

以下数字和曲线是**调校起点**，不是合格线。以真实内容、设备、操作频率和正常速度下的观看结果调整；不要为了符合参数表而保留无用运动。

### 时长

| 变化 | 可先试的范围 | 调整依据 |
| --- | --- | --- |
| 按压、开关等局部反馈 | 约 100–180ms | 反馈跟上输入，反复操作无需等动画结束。 |
| 小浮层或局部展开 | 约 150–250ms | 来源与去向可辨，同时能立即继续操作。 |
| 面板或较大区域转换 | 约 200–400ms | 距离、内容复杂度和空间关系可能需要更多时间。 |
| 解释性或叙事动效 | 按阅读节奏决定 | 允许跳过或提前操作，别把装饰时长施加到常用任务。 |

进入与退出不必等长。关闭通常以尽快恢复下一个可操作状态为目标；若退出运动帮助说明去向，仍应保留足够线索。连续打开提示或面板时，优先消除等待和队列，避免每次完整播放。

### 缓动

- 即时反馈可先试较快启动、逐渐减速；长距离屏内移动可先试两端平稳的曲线；表达稳定速率的进度可先试匀速。
- 是否使用内置或自定义曲线，取决于观看结果和现有设计语言；相近变化保持一致，无需强制自定义。
- 反向时从当前呈现的位置与透明度衔接，不突然跳回起点。先试对称路径，再依据操作节奏调整进入和退出的时间感。

### 弹簧

弹簧适合需要保留速度或可被连续操控的变化，例如拖动释放、可逆面板，并非所有进入动画的默认选择。响应时间约 0.3–0.5 秒、轻微或零过冲可作为初始试验，最终以边界、内容稳定性及中断表现调校。界面有文字和精确目标时，过冲尤其需要克制。

- **拖动中**：直接操控的对象跟随指针或手指；可选阻力只用于明确边界，不妨碍目标控制。
- **释放时**：结合当前位置、速度、可到达目标和用户意图决定落点；速度只是证据之一，不使用通用阈值或惯性公式替代场景判断。收尾从当前可见状态开始。
- **取消或反向时**：回到原位或转向新目标，维持视觉连续性；状态变化与实际操作结果一致。

例如，把列表第三项拖到第一项：拖动中让该项跟随指针，用占位提示目标位置；有效释放时从当前位置收拢到新位置，释放到无效区域或取消时返回原位。提交失败须恢复原顺序或明确提供恢复动作，不能仅凭落位动画声称保存成功。分别检查慢拖、快速释放、边界释放和中途取消；同时提供键盘移动方式，确认对象身份、选择和焦点没有随重排丢失。

### 编排

关联对象可以协调运动，以说明因果或层级。错峰、缩放、模糊和回弹都是可选表达：只有它们让关系更清楚且不拖慢使用时才采用。菜单可从触发点附近展开，抽屉可沿所在边缘进出；若布局或平台已有更清楚的约定，遵循现有方向。编排不得阻塞点击、键盘操作或内容阅读。

<a id="常见场景"></a>
## 常见场景

以下默认做法是调校起点，不是规则；产品已有约定或平台惯例更清楚时遵循它们。

### 点击弹出

适用于下拉菜单、气泡、菜单和模态框。

- 从触发点展开，`transform-origin` 设在触发点一侧；模态框可从中心或触发点轻微缩放进入。
- 进入可略慢于退出，关闭优先尽快恢复下层可操作状态。
- 遮罩与浮层分开定时：遮罩淡入淡出，浮层承担位移或缩放，二者不必等长。
- 打开时焦点移入浮层，关闭后回到触发点。
- 快速连续开关时从当前呈现状态转向新目标，不重播、不排队。

### 页面与路由过渡

- 只让发生变化的区域运动，导航栏、工具栏等持续存在的界面保持静止。
- 避免整页淡出淡入，它会让不变的部分也闪烁。
- 前进与返回的方向互为镜像。
- 返回时恢复原滚动位置。
- 过渡期间不产生布局偏移：新旧内容的占位尺寸稳定，加载中的区域先保留空间。

<a id="实现注意"></a>
## 实现注意

以下以 Web 为例；原生平台使用对应的动画框架、布局机制和系统减少动态效果设置，遵循同样的原则。

- 尽量对 `transform` 和 `opacity` 做动画，而非 `height`、`top`、`width` 等会触发布局的属性；确需尺寸变化时考虑布局动画或测量后用变换模拟。
- 退出动画结束后再卸载元素，否则元素会直接消失；卸载前停止它接收点击与焦点。
- 动画中途被打断时，从当前计算值继续到新目标，不从头重播或排队。
- 避免在动画帧中交替读取和写入布局（布局抖动）；先批量读取，再批量写入。
- 遵循 `prefers-reduced-motion` 或对应平台偏好，见下文“无障碍”。

## 哪些地方适合动画，哪些不适合

### 先检查频率

同一动画在偶发任务里可能帮助建立空间关系，在高频任务里会反复消耗时间。评估用户连续完成任务的节奏，不套用每天多少次的阈值。键盘快捷操作和密集编辑尤其需要立即反馈；少见的引导或完成时刻可容纳更明显的表达。

### 值得添加动画的连接处

- **状态关系难辨**：面板、列表项或详情区域改变后，用户找不到新旧对象的对应关系。可用短距离移动、布局过渡或高亮变化提示去向。
- **操作反馈不明**：按下后缺乏确认。先考虑静态按下状态、图标或文字；若短暂运动能改善识别，再加入。
- **手势与结果断裂**：拖动期间与释放后的落点不连续。使手势、吸附或回退构成同一动作。
- **低频情绪表达**：在不妨碍任务和阅读的时刻，适量使用节奏、回弹或装饰。

### 不要添加动画

- 动画没有增加反馈或理解，却让用户等待下一步。
- 功能数据、焦点或文字在用户阅读和操作期间无故移动。
- 自动循环、滚动视差或大面积运动分散注意，且缺少关闭途径。
- 效果只能靠慢放才被看出，正常速度下反而突兀或难以理解。

## 审查清单

| 类别 | 检查 |
| --- | --- |
| 目的与频率 | 变化是否服务于反馈、关系或状态？连续操作下是否拖慢任务？ |
| 前后状态 | 开始、进行、完成、失败及取消时的内容和可操作状态是否明确？ |
| 时序与空间 | 触发点、方向和层级是否帮助理解？正常速度下是否可辨？ |
| 可中断性 | 快速反向和重复触发是否从当前可见状态继续，会不会排队或重播？ |
| 退出与焦点 | 离场层是否停止接收操作？焦点是否到达可见、合理的下一目标且不被遮挡？ |
| 手势 | 拖动、释放、取消和边界是否与实际结果一致？不同速度的意图是否可判断？ |
| 减少动态效果 | 非必要运动能否关闭？静态反馈是否仍说明状态与结果？ |
| 一致性 | 相近变化是否复用产品已有节奏和方向，局部例外是否有任务依据？ |

先在正常速度下观看，再实际快速反向、连续触发、关闭与取消；逐帧或慢放只用于定位问题，不代替正常观看。代码检查能发现遗漏状态，不能单独证明手感；真机或目标设备的操作检查才能判断手势与焦点。

<a id="检查方法"></a>
## 检查方法

无法以正常速度观看时，可用以下可执行的检查收集证据：

- 读取计算样式或平台视图属性，确认目标元素存在预期的过渡或动画配置（如 Web 的 `transition`、时长与 `transform-origin`）。
- 在开始、中途和结束等关键时刻截取帧，并在快速连续开关时截帧，检查是否从当前状态衔接、有无跳变或残留。
- 用性能记录检查掉帧、长任务和布局偏移。

这些检查只能定位实现问题，不能代替正常速度下的人工观看；报告时说明哪些手感判断尚未验证。

## 反模式

| 现象 | 影响 | 调整方向 |
| --- | --- | --- |
| 每次触发都从第一帧重播 | 快速操作时闪跳或排队 | 从当前呈现值转向最新目标，并允许操作继续。 |
| 退出层仍可点击或困住焦点 | 误触、遮挡下层或键盘无法继续 | 关闭确定后停止其交互，将焦点转到可见的合理目标。 |
| 所有元素统一缩放、错峰或模糊 | 掩盖对象关系，也让常用动作变慢 | 只让相关对象运动，逐项说明表达目的。 |
| 拖动结束后无视位置和速度跳转 | 手势结果难以预期 | 按可到达目标和意图选择吸附或回退，并衔接当前状态。 |
| 只把运动变快作为减少动态效果方案 | 不必要的空间运动仍存在 | 关闭可省略的运动，以静态结果和状态反馈替代。 |
| 动画完成才更新语义或可操作状态 | 视觉与实际状态不一致 | 让操作、焦点和可访问状态按交互决定同步更新。 |

## 术语

用于精确表达可选模式；名称不表示必须采用。

| 模式 | 含义与适用情形 |
| --- | --- |
| 进入 / 退出 | 对象出现或离开；同时定义中断和最终可操作状态。 |
| 揭示 | 用裁切或遮罩逐步露出内容，适用于揭示关系比直接呈现更清楚时。 |
| 错峰 | 一组对象依次出现，仅在顺序有意义且不耽误任务时使用。 |
| 感知原点 | 出现位置与触发点、容器或所在边缘有关。 |
| 连续性过渡 | 连接前后对象的位置、尺寸或身份，帮助保持方向感。 |
| 共享元素过渡 | 同一视觉对象跨视图移动，例如缩略图到详情。 |
| 布局动画 | 布局改变时，相关对象过渡到新位置。 |
| 感知方向 | 用运动方向帮助区分前进、返回或层级变化。 |
| 滚动揭示 / 滚动驱动 | 出现与视口或滚动进度关联；先判断阅读价值及关闭方式。 |
| 骨架 / 微光 | 加载占位；微光是可选运动，静态骨架也能传达等待。 |
| 数字滚动 / 文字变形 | 强调内容变化；频繁更新的数据通常更适合直接替换和高亮。 |
| 按住确认 | 按住期间提示持续输入和完成时点，适合确有此需求的动作。 |
| 拖动排序 / 滑动关闭 | 对象随手势移动，并在释放或取消时到达明确状态。 |
| 橡皮筋 / 随动 / 预备动作 | 边界阻力、收尾惯性或动作前提示；需有控制与表达依据。 |
| 脉冲 / 线条绘制 | 吸引注意或说明过程，宜用于低频且可省略的场景。 |
| 交叉淡化 | 同一位置的内容通过透明度交换；检查重叠期间是否难读。 |

<a id="paired-examples"></a>
## 成对案例

以下是设计推演，方案和验证方法尚未经过实际产品测试。每组固定交互、内容、平台与任务，仅改变注明的约束。

### 1. 同一筛选面板，改变操作频率

背景固定：桌面项目工具中，工具栏“筛选”按钮打开含三个选项的侧面板；用户选完返回项目列表。按钮、面板尺寸、内容和结果保持相同。

| 版本 | 具体方案与理由 | 代价、改判条件与验证方法 |
| --- | --- | --- |
| 偶尔使用 | 面板从工具栏所在侧短距离进入，以边界变化标明层级；关闭沿原方向退出。空间线索帮助用户对应筛选控件与结果区。打开后焦点进入面板，关闭后回到按钮。 | 运动增加一次等待感。若用户连续试选项或熟练用户认为拖慢，缩短或删除位移。正常速度观看完整过程，并操作关闭、返回与焦点。 |
| 高频连续使用 | 面板立即出现，用静态边界、标题和按钮展开状态标明层级；选择可持续进行，关闭也立即恢复列表与按钮焦点。反复打开不消耗动效时间。 | 空间来源提示较弱。若新人常把面板误认成独立页面，考虑极短且不阻塞的来源提示。连续快速开关和键盘操作，检查误触、焦点与完成时间。 |

### 2. 同一筛选面板，改变减少动态效果偏好

背景固定：仍是上述桌面工具与筛选面板，且使用频率为偶尔；唯一变量是用户的减少动态效果偏好。

| 版本 | 具体方案与理由 | 代价、改判条件与验证方法 |
| --- | --- | --- |
| 默认偏好 | 使用第一组偶尔使用版的短距离进入与退出，保留边界、标题及展开状态作为不依赖运动的线索。 | 位移可能仍让部分人分心。若内容晃动或阅读被打断，应减弱或移除。正常速度观看，并在运动中快速关闭、反向重开，检查从当前状态衔接。 |
| 减少动态效果 | 面板直接呈现在最终位置，关闭时直接移除；边界、标题、按钮展开状态和焦点迁移继续说明变化。非必要位移完全关闭，不要求用淡化替换。 | 少了空间连续线索。若用户找不到面板来源，应增强静态位置、标题或按钮关联，而非恢复位移。在系统偏好下开关、键盘进入与退出，确认状态可辨且没有残留运动。 |

## 无障碍

对于由交互触发的非必要运动，应支持关闭；如果移除动画会从根本上改变信息或功能，需单独判断其必要性。[W3C 对 WCAG 2.2 成功准则 2.3.3 的说明](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)给出这一原则，以及尊重系统减少动态效果偏好或提供关闭控制等方式。这份参考不构成完整的 WCAG 合规判断。

- Web 中可使用 prefers-reduced-motion: reduce，原生界面遵循相应平台偏好；优先删除非必要的位移、缩放、视差与循环，而非一律换成透明度动画。
- 反馈必须保留：选中、展开、提交、错误等结果可通过文字、图标、对比、位置和可访问状态表达。若透明度或颜色短暂变化更清楚，可在具体场景验证后保留。
- 悬停才有的提示应考虑触摸与键盘路径；不要让动画成为获取信息的唯一办法。
- 独立于运动偏好，检查动画退出期间焦点与可操作对象，避免用户落在不可见或被遮挡的控件上。
