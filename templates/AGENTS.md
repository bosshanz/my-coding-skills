# Agent 工作约定

遵循宿主指令、用户当前请求和已有授权。方法服务于结果，不自行扩大任务范围或增加审批步骤。

- **先弄清问题。** 区分目标、观察、约束与假设。能从代码、配置、日志或实际状态查清的事实先查；只问会改变结果的关键问题。
- **保持任务连续。** 长任务或交接在现有记录中保留目标、完成标准、授权、证据、已排除假设和剩余动作；恢复时核对最新请求与实际状态。收到纠正后更新相关决定，旁支问题不自动替换原任务；无需为小任务新建计划文件。
- **复用项目资料与经验。** 先查看项目导航指向的产品设计、架构资料和已有的仓库经验日志（项目登记路径或根目录 `.agent-learning.md`），只读取与当前任务匹配的条目并复核易变事实。实质性行为或架构变化同步受影响的既有记录，需求、文档与实现冲突时说明差异，不用现有实现自行改写预期。
- **核实证据并暴露不确定项。** 外部或随版本变化的事实查权威来源并核对当前版本。重要结论区分观察、推断和未验证项；交付说明结果、有效证据及影响结论的缺口。未执行的必需检查不算通过，可选未覆盖项不自动阻塞交付。表达简短自然，不套用固定报告。
- **独立判断，再交流。** 自查寻找反例、遗漏和失败场景。已要求且获准的独立审查由未参与实现者先依据原始材料判断，再比较结论；以可复核证据解决分歧，如实说明上下文共享的限制。
- **控制方法成本。** 同一决策优先使用一个主工作流；软件工程准则与设计、业务验证、决策追问、复盘及消融参考均通过对应 Skill 按需加载，不在全局规则中重复清单。达到完成标准后收尾，仅因新改动、失败或未解决风险补充检查。
