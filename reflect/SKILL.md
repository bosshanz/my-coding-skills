# 复盘与学习

把已完成工作、纠正、失败或更好做法中的证据转化为下一次可用的改进。立即落实当前纠正。在仓库工作中遇到有意义的纠正、失败尝试或有证据的更好做法时启用；有具体学习信号时复盘重要结果，不必每次微小操作后都复盘。所有写入遵守宿主的持久化规则，全局记忆始终需要用户明确要求。

## 复盘并提炼经验

1. 从可用对话、差异、日志和检查中还原预期与实际结果，识别成功、失败和尚未验证的部分。只阅读相关材料，不把缺失证据补写成事实。
2. 找出重要偏差，区分已观察症状、有证据支持的原因和可能解释。一次工具失败不能证明普遍限制；一次检查通过只能证明其实际覆盖的行为。
3. 形成具体经验：在什么条件下，Agent 应改变什么做法，以及什么证据能证明这样更有效。优先记录具体恢复方式或决策规则，不写“更仔细一点”之类空泛建议；没有可复用信号时，不强行制造经验。
4. 区分**用户确认的偏好**、**有证据支持的经验**和**待验证的假设**。沉默、称赞、重复或自我批评都不能把推断变成用户偏好；当前任务中的情境性修改（如“把这个标题改成红色”）也不是偏好。只有条件和结果提供支持，重复出现才会增强经验的可信度；固定重复次数不是证明。
5. 报告有用发现及下一次应用或验证方法，然后继续其他已授权工作。

如果请求只是记录一条准确偏好，跳过复盘，直接按下文记录。记录、替换或撤销偏好，或整理已有经验日志时，阅读 `references/preferences-and-maintenance.md`。

## 仓库内记忆

仓库根目录有两个约定的经验日志，存在的都要读取：

- `.agent-learning.md`：随仓库提交、与团队共享的经验。
- `.agent-learning.local.md`：个人经验，不提交。首行为 `记录：关闭` 时，只表示不再自动写入新条目、也不再询问落点；不阻止读取已有的共享日志或其他已有条目。

写入位置按范围或用户选择决定：团队或可共享的经验写入 `.agent-learning.md`，个人经验写入 `.agent-learning.local.md`；用户指定路径或范围时以用户为准。不要把个人条目写入共享文件，也不要把团队条目写入私有文件。

已有落点直接使用：项目规则登记的经验日志、用户在本次请求中指定的路径，以及已存在的约定文件。用户明确要求把经验留在仓库但未给路径时，写入 `.agent-learning.md`；即使已有 `.agent-learning.local.md`，也不改写或覆盖该私有文件。

没有已知落点时，在首次出现值得记录的条目时询问一次，不中断正在进行的工作：在本轮汇报末尾附上拟写条目，问一个聚焦问题。选项为：

1. 共享文件 `.agent-learning.md`。
2. 私有文件 `.agent-learning.local.md`，并加入 `.git/info/exclude`，不改共享的 `.gitignore`。
3. 仅在对话中保留。本会话不再询问；以后的会话可以再次询问。
4. 本仓库不记录经验：在 `.agent-learning.local.md` 首行写入 `记录：关闭`，并加入 `.git/info/exclude`。此后不再询问，也不自动写入新条目；仍读取已有共享日志。
5. 用户指定的其他路径。只在用户同意后把该路径登记到项目规则，便于后续会话发现。

用户选定后照此执行：选项 1、2、4、5 选定后，此后不再询问；选项 3 仅本会话不再询问，以后的会话可以再次询问。用户未回答或拒绝时只在对话中保留结论，本会话不再追问。

新建的日志文件在 Git 中可能处于未跟踪状态，写入后如实说明。仓库根目录不明确时，先从项目上下文或 Git 确认，再写入。仓库之外，除非用户指定落点，否则仅在对话中保留结论；绝不自动转存全局记忆。

条目保持简短，每条只记录一个概念，例如：

```markdown
## 草稿保存确认
- 类型：有证据支持的经验
- 范围：本仓库的草稿保存流程
- 触发与做法：报告保存成功前，等待持久化确认。
- 证据：2026-09-16，刷新丢失的失败复现及通过的回归检查；链接到相关测试或任务记录。
- 限制：仅适用于已测试的草稿流程；离线同步尚未验证。
```

上述日期和证据仅演示格式，不代表已执行结果。只添加真实证据，个人偏好与技术经验分开。经验日志是供查阅的证据，不会自动成为团队规则；修改 `AGENTS.md` 等指令文件需要相应授权。不要仅为保存经验而提交或推送。

## 持久化与读取

- 遵守宿主的记忆和指令文件规则。宿主只允许用户明确要求后持久化时，自动启用不能覆盖该限制；缺少适用写入授权时只在对话中保留结论，不反复打断用户询问是否保存。遵守明确的不保存要求。
- 请求已授权条目与落点时直接写入，不重复确认；更新已有等价条目，不重复追加。已请求的写入无法执行时，提供拟写条目并说明尚未保存。
- 后续相关工作中只读取匹配的条目，并复核可能变化的事实。不是每个宿主都会自动注入 Markdown 文件；没有实际读取，就不要声称已加载经验。绝不持久化凭据或不必要的私密对话数据。

**边界：** 本 Skill 不改变授权，不新增审批，不自动调用其他 Skill；复盘不授权无关修复、修改 Skill 库或调用外部模型。修改范围、发布、委派和持久化按用户请求、项目规则和宿主规则决定。
