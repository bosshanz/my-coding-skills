# 偏好记录与经验日志维护

记录、替换或撤销用户偏好，处理链接 worktree 边界，或整理已有经验日志时阅读。日常复盘和常规落点判断见 `SKILL.md`。

## 记录偏好

- 明确条目的类型、范围、证据或来源及可信度；不从单次情境修改或普通产品需求推导通用规则。
- 直接使用用户已确认的内容与落点，无需重复确认；无法实际执行写入时，直接给出拟写条目并说明未保存原因。
- 只有明确获准时才写入项目规则（如 `AGENTS.md` 的偏好段），保留无关指令；不把私有宿主记忆复制到共享仓库，也不借记录偏好修改本 Skill 库。

<a id="scope-conflicts-and-retraction"></a>
## 作用域、冲突与撤销

个人偏好与团队约定分开存储；打开仓库不代表获准写入团队共享规则。写入前检查已有同范围条目：明确替换时直接更新原条目，窄范围例外与原规则并存，明确撤销时仅移除或标记对应条目失效（宿主有专门更新机制时按宿主方式处理），不反推相反偏好。

| 用户表达 | 处理方式 |
| --- | --- |
| `$reflect` 将“本项目使用 pnpm”记录到指定项目文件 | 按项目范围记录一次，注明来源，不重复确认。 |
| 普通编辑中说“把这个标题改成红色” | 完成修改，不推断或持久化“偏好红色标题”。 |
| `$reflect` 把本项目的 pnpm 偏好替换成 npm | 替换同范围旧条目，保留无关和其他项目条目。 |
| `$reflect` 记录“旧包用 npm，其他包继续用 pnpm” | 添加包级局部例外，不覆盖整体规则。 |
| `$reflect` 撤销先前偏好 | 仅撤销该条目，不推导出相反偏好。 |
| 日常纠正产生经验，但仓库尚无经验日志 | 先完成当前工作，汇报末尾附拟写条目询问一次落点；未回答则只留在对话中。 |

## 链接 worktree 与路径边界

- **主工作树定位**：在链接 worktree 中，未跟踪的 `.agent-learning.local.md` 不会随分支出现在当前目录，读写及 `记录：关闭` 检查均针对 `git worktree list --porcelain` 第一项指向的主工作树根目录。若第一项标为 `bare`（无主工作树），退回当前工作树根目录；主工作树不可访问时如实说明，新条目仅在对话中保留。
- **Git 排除文件**：写入本地忽略规则时，使用 `git rev-parse --git-path info/exclude` 解析实际路径（链接 worktree 中 `.git` 是文件而非目录，不能硬拼 `.git/info/exclude`），不改动共享的 `.gitignore`。
- **仓库外工作**：仓库根目录不明确时先通过上下文或 Git 确认；不在仓库内且用户未指定落点时，仅在对话中保留结论，绝不自动写入全局记忆。

## 整理经验日志

条目较多需要整理时，才使用简短索引加按需详情的结构；少量条目保持单文件扁平记录。获准维护时，合并重复项、按新证据更新过时经验并保留有效来源：不因时间久远静默删除已确认偏好，不把假设自动升级为规则，也不因安装或调用本 Skill 自行添加定时或心跳任务。

## 经验示例

- **症状与根因分开**：界面提示已保存但刷新丢失。若日志证实提示早于持久化确认，可记录等待确认的边界经验；根因未查清前，只记症状和待查项（假设），不断言数据库故障。
- **限定版本与条件**：某命令因本地版本不支持旧参数而失败，查本机帮助确认新参数可用后，只记录该版本下的参数经验，不推导“该 CLI 不可用”。
- **不保存要求**：用户要求“只复盘不保存”时，在对话中给出提炼结果，不触碰任何记忆或日志文件。
