# 按需能力与证据

## 普通工作直接完成

所有开发任务以 `eng` 的工程原则为共同入口，约束取舍而不规定固定步骤。当前 Agent 负责理解目标、实现、验证和交付；无需先进入 `dev` 或 `clarify`。项目命令、领域约束和已有授权优先。用户要求不用 Skill 时，直接工作。

需要具体设计决策时查阅 `design` 中相关资料；业务规则检查、真实旅程诊断或最终验收使用明确请求的 `verify`；挑战方案可请求 `grill-me`；纠正、失败和有证据的改进可触发 `reflect`，将经验留在仓库并遵从宿主记忆规则。它们不是自动流水线。`verify` 仅评审时只读，要求保护规则时可改测试，修复已授权时继续实施。Skill 切换不重置授权，也不授权外部 CLI、发布或生产操作。

工程入口遵循“如无必要，勿增实体”等共同准则，配套资料按需加载，文件在 [eng/references/](../eng/references/)。只读当前决策需要的那一份。`skills references` 显示打包路径。

## 把指导转成可检查的结果

| 能力 | 当前资料提供什么 | 如何判断这次任务完成 |
| --- | --- | --- |
| `design` | 交互与视觉参考、不同产品情境的选择示例 | 设计请求交付符合 brief 的方案；实现请求检查实际界面与受影响行为。已有系统不必重新建立视觉身份。 |
| `eng` | 简洁、可维护表达、清晰契约、真实失败、状态归属和兼容性等准则，以及行为测试、依赖成本和实际交付物的按需参考 | 完成符合约束的已授权开发工作；原则体现在结果中，不要求固定步骤或合规报告。 |
| `verify` | [场景与证据对应关系](../verify/references/scenarios.md) | 对用户指定行为给出可复现发现或有依据的结论，不为报告数量制造问题。 |
| `grill-me` | 基于证据，一次一个关键问题的决策访谈 | 收敛已定选择、约束、剩余假设与下一步；用户要求结束时停止追问。 |
| `reflect` | 日常复盘、仓库内经验积累，以及偏好的去重、替换和撤销 | 证据与假设分开；在宿主允许的仓库位置维护经验，明确要求才写入全局。 |

证据的新鲜度取决于代码版本、配置、输入和依赖是否仍适用，不取决于是否刚刚再次运行了一遍命令。相关条件发生变化时重新检查；未变化的有效证据可复用。截图说明外观，实际交互说明操作行为，存储或服务方记录说明权威效果，不能相互代替。

例如，支付重试只有本地记录时，不能证明服务方没有重复扣款；草稿刷新通过也不能证明服务端重启恢复。先选包含实际执行机制的最小检查，再说明覆盖范围。测试真实付费或生产操作需要对应授权，场景资料不提供这种授权。

## 安装和升级

安装与卸载均需明确选择 Skill 或分组，无参数只显示帮助；默认目标为 `agents`。`all` 是显式的全量选择。安装器不自动清理历史目录；卸载器保留旧名称用于迁移，见 [迁移说明](../README.md#从旧目录迁移)。

外部 CLI 由可选的 `external-cli` 选装。共享调用协议在该 Skill 入口；各 CLI 速查在 `external-cli/references/`。目标收到原任务、文件范围、现有授权和用户对 Skill 的选择或禁止；普通开发无需在目标中另行选择开发工作流。默认用各家无头命令；ACP 只用于有客户端的会话或编辑器嵌入。

## 检查分别证明什么

| 检查 | 证明范围 | 命令 |
| --- | --- | --- |
| 静态检查 | 目录、引用、fixture、安装安全及校验器正反例 | `npm test` |
| 资源检查 | 必需文件、脚本与可选 CLI 状态 | `npm run doctor` |
| 路由代理 | description；extended 模式另含 when_to_use | `npm run eval:routing -- --surface description` |
| 文本回答 | 关键词、正则及范围信号；不证明工具行为 | `npm run eval:behavior` |
| 宿主自报 | 已授权 CLI 声称会选哪个入口 | `npm run eval:e2e -- --cli <目标>` |
| 真实执行 | 临时项目的文件变化和可观察行为 | `npm run eval:execution -- --prepare` |

代理路由不包含所有宿主规则或 invocation policy。dry-run 只检查加载。文本评估的 Claude 结果不是 Codex 结果；自报选中 Skill 也不证明实际加载。首次失败保留，路由 `--recheck` 仅诊断；回答 `--attempts` 保留各次输出。`--record` 保存摘要和原始 JSON。

现有 nightly 仍运行路由与文本代理，需要 `ANTHROPIC_API_KEY`，不自动启动真实执行 Agent。当前任务未授权外部模型时，仅运行静态检查；修改 fixture 不等于该行为已通过模型验证。

### 工程决策的成对案例

`evals/behavior/fixtures.yaml` 中的 `eng-decision-*` 包含抽象、状态归属、失败回退、兼容和验证强度五组案例。每组保留问题背景，只改变关键约束，预期选择随证据改变。明确结论行仅用于判定选择，避免同时提及两个选项就通过；不是日常工程回答格式。

当前文本 runner 仅加载 `SKILL.md`，没有工具，也不会读取 references。正则通过仅说明选择和部分措辞符合预期；应按案例中的 `review_notes` 复核方案是否保住约束、代价是否合理、何种新证据会改变决定。复述原则、选项正确但方案违反约束，均不能算决策质量通过。

要判断本轮参考补充的效果，需在已授权的对照中让两个版本实际读取对应参考，固定任务、模型、权限和预算，保留原始输出并成对比较；不能把入口文本评估当作 references 的效果验证。案例干跑只证明夹具可加载，尚未运行的模型对照保持未验证。

## 真实执行夹具

1. 运行 `npm run eval:execution -- --prepare` 创建全新的临时目录。
2. 在已授权的 Agent 中，以独立上下文执行各 `*.task.txt`；只提供任务文件，不提供 verifier、manifest 或预期答案。
3. 原样保存实际最终回复到对应的 `<case>.response.txt`，检查运行记录中的多余确认、越界动作或虚报。
4. 运行 `npm run eval:execution -- --verify <目录>`，结果追加到 `attempts.jsonl`。每次模型尝试重新 prepare，记录宿主、实际可知的模型、版本与全部尝试。

当前三个场景覆盖实现、仅评审、已有授权后的继续，不再复制或强制加载 `dev`；它们是当前宿主直接工作的局部基线，不能证明所有可选 Skill 的效果。宿主已有规则、记忆和全局 Skill 仍可能影响运行，应记录真实环境；“夹具不注入 Skill”不等于完全裸模型。

prepare / verify 不会启动 Agent，也不修改全局安装。临时目录不是安全沙箱。文件快照检测不到写入后撤销等过程行为；继续场景提供单次输入中的已有上下文，不代表完整的多轮实测。历史报告保持原始口径。

判断可选 Skill 是否值得保留，需要同模型、同任务、同环境、同权限和相当预算的有无对照，以及质量、失败、耗时等结果。不要把静态通过或单次通过当成增益证据。比较设计可查阅 [消融资料](../eng/references/ablation.md)，是否实际调用外部模型仍以授权为准。

## 后续比较如何开展

比较对象可以是“不加载该 Skill”“当前版本”“候选版本”。这里的“不加载”只移除待评估的可选 Skill，保留正常宿主规则、权限和保护措施，并记录其他已安装能力的影响。

- 使用相同任务、初始代码与数据、宿主和模型配置、工具权限以及相当预算；每次从隔离初始状态开始，避免前一次产物泄漏答案。
- 先定义可观察结果，再运行：例如重复请求的实际效果数量、跨租户访问是否被拒绝、刷新后的草稿内容、偏好是否写到正确作用域。
- 同时记录缺陷遗漏、错误修改、返工、耗时和可获得的用量。设计质量包含人的判断，应保留 brief、实际产物和评价依据；单一分数不替代这些材料。
- 按风险和波动选择重复次数，保留所有尝试及失败。小样本结果仅说明所测任务，不外推为所有模型和项目的提升。

上述比较方案尚不代表已经执行。现有真实执行夹具也未覆盖这些新增参考场景；必须为选定任务准备合适的输入和结果检查。是否调用模型、外部 CLI 或独立审查者，仍以当前授权为准。
